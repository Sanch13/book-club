# PROJECT_CONTEXT.md — Корпоративный книжный клуб Miran (2026)

Этот файл является единым источником контекста для AI-агентов и разработчиков, работающих над проектом Miran Book Club.

## 1. Общие сведения
- **Проект:** Закрытый сайт корпоративного книжного клуба Miran.
- **Цель:** Управление списком книг на 2026 год, голосование участников (1–10 баллов с возможностью изменения до конца года), публикация отзывов, отображение статистики и анонсов встреч.
- **Стек технологий:**
  - **Python:** 3.13
  - **Фреймворк:** Django 6.x
  - **Менеджер пакетов:** `uv`
  - **База данных:** SQLite (для разработки), подготовка под PostgreSQL
  - **Приложения:** `club` (книги, голоса, отзывы, встречи), `user` (модель пользователя, регистрация, вход/выход)
  - **Frontend:** Django Templates, Tailwind CSS, Alpine.js
  - **Тестирование:** `pytest`, `pytest-django`
  - **Линтер/Форматировщик:** `ruff`

## 2. Роли и права доступа
- **Админ (admin):** Управление пользователями, книгами (12 книг 2026 года, янв–дек), файлами книг (PDF/MP3/MP4), встречами, просмотр голосов и отзывов.
- **Участник (participant):** Регистрация по email и паролю, авторизация по email и паролю, голосование (1–10) с возможностью изменения до 31.12.2026, добавление нескольких отзывов на книгу, редактирование только своих отзывов.
- **Поля пользователя:** логином является `email` (уникальный, обязательный). Поле `username` в модели отсутствует.
- **Белый список (`WhitelistEmail`, приложение `user`):** регистрация и вход возможны **только** если email есть в белом списке с `is_active=True`. Email нормализуется к нижнему регистру при сохранении (`normalize_email`) и при проверке. Администратор управляет списком в админке (добавление, деактивация, массовые actions «Активировать» / «Деактивировать»).
- **Ограничения:**
  - Удаление отзывов запрещено для всех ролей.
  - Изменение голосов блокируется после 31.12.2026 (по серверному времени).
  - Список проголосовавших виден всем (`Фамилия Имя — rating`). Если ФИО не заполнено — показывается `email`.
  - Все отзывы видны всем сразу, сортировка новые → старые.

## 3. Сущности (Models)
1. `User` (Custom User Model, приложение `user`): `email` (уникальный, обязательный, используется как логин), `role` (`admin`, `participant`). Поле `username`/`login` отсутствует. Поля `first_name`/`last_name` — необязательные, редактируются пользователем в личном кабинете (`/profile/`), вместе со сменой пароля. Email из кабинета не меняется (он же логин и ключ белого списка). Свойство `display_name` возвращает `Фамилия Имя`, если заполнены оба поля, иначе `email`. Используется в отзывах, комментариях и списке проголосовавших.
2. `Book`: `year` (2026), `month` (1..12), `title`, `author`, `short_description`, `cover_image`. Поле `book_page` («Страница книги / Ссылка») удалено — файлы хранятся в `BookAttachment`. Средний балл вычисляется динамически.
3. `BookAttachment` (файлы книги): `book` (FK), `file_type` (`pdf`, `mp3`, `mp4` — только те форматы, которые браузер открывает сам; PPT/PDF Office исключены), `file` (необязательный), `title` (необязательное название; если пусто — показывается имя файла). Свойства `file_name`, `display_name`, `has_file` (учитывает наличие файла в хранилище), `file_url`. Если файла нет — на странице книги серая заглушка «Файл не прикреплён». Администратор добавляет файлы через inline на странице книги в админке.
4. `Vote`: `book` (FK), `user` (FK), `rating` (1..10), `updated_at`. Уникальная пара `(book, user)`.
5. `Review`: `book` (FK), `user` (FK), `text`, `created_at`, `updated_at`. Множественные отзывы разрешены.
6. `ReviewComment`: `review` (FK), `user` (FK), `text`, `created_at`. Комментарии только создаются — правки и удаление не предусмотрены.
7. `Meeting`: `title`, `date_time`, `location`, `description`.

## 4. Бренд-стандарты (Визуальное оформление)
- Фирменные цвета Pantone:
  - **Pantone 382C** (`#A2D813`) — яркий акцентный зелёный.
  - **Pantone 424C** (`#707372`) — благородный корпоративный серый.
- Шрифты: стандартные веб-шрифты (Inter / Roboto / Arial).

## 5. Регламент работы (Step-by-Step Protocol)
- Все задачи делятся на минимальные логические шаги.
- Перед каждым шагом агент предоставляет план и запрашивает подтверждение («Да / Корректировка»).
- Изменения в код вносятся только после явного одобрения пользователя.
- После выполнения каждого шага агент демонстрирует сделанные изменения (файлы, фрагменты кода, результаты тестов) для проверки и ревью.
